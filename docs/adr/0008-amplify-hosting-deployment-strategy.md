# ADR 0008: Amplify Hosting のデプロイ戦略（CI/CD連携回避と手動デプロイ）

## コンテキスト
フロントエンド（Reactアプリケーション）をAWS Amplify Hostingにデプロイし、オンラインで公開するためのインフラ構築が求められた。
Amplify Hostingへのデプロイ方法には、主に以下の2つのアプローチがある。
1. **リポジトリ連携 (CI/CD)**: GitHubなどのリポジトリとAmplifyを連携させ、特定のブランチへのPushをフックにして自動ビルド・デプロイを行う方式。
2. **手動デプロイ (Manual Deployment)**: ローカルや任意の環境でビルド済みのアーティファクト（ZIPファイル等）を作成し、AWS CLIやコンソール経由で直接Amplifyにアップロードする方式。

IaC (Terraform) でリポジトリ連携を構築する場合、GitHubのパーソナルアクセストークンやOAuthトークンをTerraformのシークレットとして管理する必要がある。

## 決定
**手動デプロイ方式（アプローチ2）を採用**し、インフラ（Amplifyの枠組みや環境変数）のプロビジョニングのみをTerraformで行い、ソースコードのデプロイメントはAWS CLIを用いた手動スクリプト（`deploy.sh`）で実行する構成とした。

## 理由
- **トークン管理の負荷軽減**: 本番利用を見据えた場合、誰が発行したGitHubトークンをTerraformで管理・運用するのかというセキュリティ・運用上の課題（ローテーションの手間など）が発生するため、これを回避したかった。
- **デプロイタイミングの制御**: `main` ブランチにPushされたら即時デプロイされるのではなく、任意のタイミングでローカルから明示的にデプロイ作業を行いたかったため。
- **インフラとアプリのライフサイクルの分離**: IaCのベストプラクティスに基づき、「Amplifyの箱と設定の用意」はTerraformで行い、「頻繁に行われるソースコードの入れ替え」はAWS CLIで行うことで、Terraformの責務を明確にした。

## 課題と対策（トレーサビリティの確保）
手動デプロイは、リポジトリ連携と異なりAmplifyのコンソール画面上で「どのコミットがデプロイされたか」が自動表示されないという欠点がある。複数人での運用において「何がデプロイされたか分からない」という状態を防ぐため、以下の対策をスクリプト（`deploy.sh`）に組み込んだ。
1. **アプリ内へのハッシュ埋め込み**: ビルド時に `git rev-parse HEAD` で取得したコミットハッシュを環境変数として注入し、Reactアプリのフッターに表示させる。
2. **Amplifyリソースへのタグ付与**: AWS CLIでアップロードが完了した後、Amplify Branchのリソースタグ（`LastDeployCommit`, `LastDeployUser`）を最新の情報で上書き更新する。これによりAWSコンソールからデプロイ状況を追跡できる。
