# 7. E2Eテストフレームワークとしての Playwright の採用

Date: 2026-09-06
Status: Accepted

## Context (背景と課題)
Phase 5 のフロントエンド実装において、フロントエンドの単体テスト（`vitest` ＋ モック）は全てパスしていたにも関わらず、実際のブラウザで動作確認をすると画面が正しく表示されないというバグが発生した。
原因は、バックエンド (FastAPI) が返す実際の JSON 構造 (`{"status": "success", "profile": {...}}`) と、フロントエンドのテストコード内で定義していたモックの構造 (`{...}`) が一致していなかったこと（インターフェースのズレ）である。
このように、単体テストでは防ぎきれない「結合時のバグ（モックの罠）」を未然に防ぐため、本物のバックエンドインフラと通信を行う End-to-End (E2E) テストの導入が必要となった。

## Decision (決定事項)
フロントエンドの E2E テストフレームワークとして **Playwright** を採用する。

本プロジェクトの制約として、CI/CD パイプライン上での自動実行は当面スコープ外とし、「ローカル開発環境で `npm run dev` を立ち上げ、すでに構築済みの AWS 本番リソース（Cognito, API Gateway, DynamoDB）と直接結合してテストする」というローカル実行特化の運用とする。

## Consequences (結果)
* **Good**: モックを一切使用せず、実際のインフラ (AWS) を貫通したテストがローカルで容易に実行可能になるため、インフラ設定ミスや API レスポンス仕様の変更による破壊的変更を確実に検知できるようになった。
* **Good**: Cypress ではなく Playwright を採用したことにより、Vite 環境との親和性が高く、将来的な複数ブラウザテストや並列実行への移行が容易になる。
* **Bad**: テストを実行するためには、AWS 上に検証用リソースがデプロイされており、かつテスト用のアカウントが Cognito 上に存在している必要がある（環境依存性が高い）。
