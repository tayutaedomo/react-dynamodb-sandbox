# 3. DynamoDB と PynamoDB (ORM) の採用

Date: 2026-09-06
Status: Accepted

## Context (背景と課題)
バックエンド（FastAPI + AWS Lambda）から利用するデータベースとして、サーバーレスアーキテクチャと相性の良いデータストアを選定する必要があった。
また、Python (boto3) から DynamoDB を直接操作する場合、スキーマレスであるゆえにコード上でデータ構造（モデル）が不透明になり、認知負荷の増大や保守性の低下を招く懸念があった。

## Decision (決定事項)
1. **データベースに Amazon DynamoDB (PAY_PER_REQUEST) を採用する。**
   Lambda との相性（接続プーリング問題がない点）、フルマネージドな運用保守性、および小規模からスタートできるコスト効率を評価した。
2. **DynamoDB の操作ライブラリとして PynamoDB (ORM) を採用する。**
   `boto3` の直接利用を避け、`pynamodb.models.Model` を継承したクラスによってスキーマを明示的に定義する。

## Consequences (結果)
* **Good**: Lambda のコールドスタートや同時実行数のスケールに対して、RDBMSのようなコネクション枯渇を心配することなく柔軟にスケールできる。
* **Good**: コードベース上で「テーブルにどのような属性が存在するか（`user_id`, `nickname` 等）」が一目瞭然となり、開発体験と保守性が大きく向上する。
* **Bad**: 複雑なクエリ（複数テーブルを跨ぐ JOIN や集計処理など）が必要になった場合、DynamoDB の設計（シングルテーブルデザインなど）の学習コストが発生する。
